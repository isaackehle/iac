# Markdown Linting with rumdl

This document describes the rumdl pre-commit hook setup for the IAC repo.

## Overview

All markdown files are automatically linted and formatted on commit using:

- **rumdl**: Rust markdown linter (fast, modern)
- **lefthook**: Git hook framework

## Files

- `.rumdl.toml` - rumdl configuration
- `lefthook.yml` - lefthook hook configuration
- `.git/hooks/pre-commit` - installed hook (auto-generated by lefthook)

## Configuration

### `.rumdl.toml`

```toml
[global]
exclude = [
    ".gitignore",
    ".pre-commit-config.yaml",
    "package.json",
    "package-lock.json",
    "CHANGELOG.md",
    "tests/**/*.md",
    "__tests__/**/*.md",
]

[MD013]
line_length = 160
code_blocks = false
tables = false

[MD036]
enabled = false

[MD041]
enabled = false

[MD007]
indent = 2

[MD033]
allowed_elements = ["code", "kbd", "pre", "samp", "var"]
```

**Rules:**

- **MD013**: Line length ≤ 160 chars (auto-wrapped)
- **MD036**: Disabled (intentional emphasis)
- **MD041**: Disabled (some files don't need headings)
- **MD007**: List indent = 2 spaces
- **MD033**: Only allow safe inline HTML

### `lefthook.yml`

```yaml
pre-commit:
  parallel: true
  commands:
    rumdl:
      glob: "*.md"
      run: rumdl --config .rumdl.toml fmt
```

**How it works:**

- Runs on `pre-commit` hook
- Parallel execution for multiple commands
- `glob: "*.md"` - only runs on markdown files
- `rumdl fmt` - auto-fixes formatting issues
- Reports remaining issues (long lines, etc.)
- Commit proceeds if auto-fix succeeds

## Usage

### Automatic (on commit)

```shell
git add .
git commit -m "your message"
```

The hook will:

1. Run `rumdl fmt` on all `.md` files
2. Auto-fix what it can
3. Report issues that need manual attention
4. If issues remain, commit is blocked

### Manual Testing

```shell
# Run on all files
rumdl --config .rumdl.toml fmt .

# Check only (no auto-fix)
rumdl --config .rumdl.toml check .

# Test on single file
rumdl --config .rumdl.toml fmt docs/007_markdown_linting.md

# Run lefthook manually
lefthook run pre-commit
```

## Common Issues

### Long Lines (> 160 chars)

**Problem:**

```markdown
This is a very long line that exceeds the 160 character limit and needs to be broken up into multiple lines.
```

**Fix:**

```markdown
This is a very long line that exceeds the 160 character limit
and needs to be broken up into multiple lines.
```

**Or use code blocks:**

```markdown
See the command:

```shell
long-command-with-many-arguments --flag1 --flag2 --flag3
```

```text

### Headings with Colons

**Problem:**

```markdown
### Shabbat Services:
```

**Fix:**

```markdown
### Shabbat Services
```

**Note:** MD036 is disabled, so this won't block commits, but it's good practice.

### URLs

**Problem:**

```markdown
See https://very-long-url.com/with/many/segments/that/exceed/limit
```

**Fix:**

```markdown
See [documentation](<https://very-long-url.com/with/many/segments/that/exceed/limit>)
```

### Code Blocks Without Language

**Problem:**

```markdown
```

code without language

```text
```

**Fix:**

```markdown
```shell
code with language
```

```text

## Excluded Files

The following are excluded from linting:

- `.gitignore`, `.pre-commit-config.yaml`
- `package.json`, `package-lock.json`
- `CHANGELOG.md` (auto-generated)
- `tests/**/*.md`, `__tests__/**/*.md`

## Troubleshooting

### Hook Not Running

```shell
# Reinstall hook
lefthook install

# Test manually
lefthook run pre-commit
```

### rumdl Not Found

```shell
# Install rumdl
cargo install rumdl

# Verify
which rumdl
```

### Configuration Errors

Check `.rumdl.toml` syntax:

```shell
python3 -c "import tomllib; tomllib.load(open('.rumdl.toml', 'rb'))"
```

Check `lefthook.yml` syntax:

```shell
python3 -c "import yaml; yaml.safe_load(open('lefthook.yml'))"
```

## Best Practices

1. **Keep lines under 160 chars** when possible
2. **Use code blocks** for long commands
3. **Wrap URLs** with angle brackets or links
4. **Add language specifiers** to code blocks (```shell, ```text, etc.)
5. **Run `rumdl fmt` locally** before committing
6. **Review hook output** to understand issues
